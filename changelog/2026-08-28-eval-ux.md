# 2026-08-28 — eval:ux, l'eval e2e dell'esperienza utente

## Perché

La task Notion #34 chiede test e2e globali in cui l'AI verifica che l'esperienza utente sia quella
voluta, partendo dall'onboarding, con un comando solo appigliabile a un agente in cron. Fino ad
oggi l'unico e2e è la smoke suite db-free di Playwright (`tests/e2e/`), che non tocca né
l'onboarding né la chat: non c'era nulla che misurasse l'esperienza.

## Cosa c'era prima

Niente. In package.json restava solo il riferimento pendente `test:durability → eval:durability`;
`scripts/eval/` e `docs/EVAL_PLAN.md` citati da AGENTS.md non esistevano. Questo è il primo pezzo
di quell'harness.

## Decisioni

- **Hybrid walker, non agente libero**: la camminata (login → onboarding → pick → setup chat) è
  una sequenza deterministica di comandi agent-browser (vercel-labs) con attese esplicite; il
  giudizio sulle impressioni attese è un turno LLM (geminiFast) su snapshot a11y + fatti DB.
  Un agente libero sarebbe non riproducibile e a costo per run variabile (ricerca
  `docs/research/2026-08-28-agent-browser-e2e.md`, issue #1351); Playwright resta per la
  regressione.
- **Utente eval usa-e-getta via GoTrue admin** (stesso percorso di `db-seed.mjs`): l'onboarding
  parte da un utente senza org/brand, così è il prodotto a crearli. Il teardown cancella l'utente
  (cascata su brand/chat) e svuota `media/<userId>/` su Storage — sempre, anche su fallimento.
- **Fatti prima dei gusti**: la griglia di `scripts/eval/ux/grader.ts` separa i gate deterministici
  (brand creato, risposta dell'agente nella chat di setup entro la finestra) dal giudizio LLM sui
  quattro criteri della task. L'exit code è 0 solo se gate e criteri passano tutti.
- **Server auto-avviato**: se l'app non risponde su `EVAL_UX_APP_URL` (default
  `http://localhost:4180`), il comando avvia da solo `vite dev` e lo chiude alla fine; report,
  evidenze (screenshot + snapshot), transcript e log del server finiscono in `eval-results/<run>/`.
- agent-browser si invoca via `npx -y agent-browser` (v0.35.1, binario Rust, nessuna dipendenza
  aggiunta al package.json).

## Scartato

- Giudizio multimodale sugli screenshot: v1 giudica dagli snapshot a11y; le PNG restano come
  evidenza umana. v2 possibile.
- Percorso wizard completo (people → competitors → strategy → plan → preview): il percorso v1 è
  chat-prima ("Inizia la chat" dalla pick), quello che la task #34 descrive. I piani editoriali
  sono riportati come informazione, non come gate.
